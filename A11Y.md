# Accessibility Improvements

## 1. Semantic HTML & Structure
We have prioritized the use of semantic HTML elements throughout the application to ensure compatibility with screen readers and other assistive technologies.
- **Landmarks**: We utilized `<header>`, `<main>`, and `<section>` (via Ant Design's `Layout` components) to clearly define the page structure.
- **Headings**: A proper heading hierarchy (`<h1>` to `<h5>`) is maintained on every page (e.g., Listing Title is `<h2>`, section headers are `<h3>` or `<h4>`). This allows screen reader users to navigate by jumping between headings.
- **Lists**: We used `<ul>` and `<li>` elements (via `List` component) for collections of items like reviews, bookings, and amenities, ensuring the number of items is announced.

## 2. Keyboard Navigation
The entire application is navigable using only a keyboard.
- **Focus Management**: Interactive elements like buttons, inputs, and links have visible focus states.
- **Tab Order**: The logical flow of the DOM ensures that the `Tab` key moves focus in a predictable manner (left-to-right, top-to-bottom).
- **Modal Handling**: When modals (e.g., "Create Listing", "Filters") open, focus is trapped within the modal until it is closed, preventing users from accidentally interacting with background content.

## 3. Forms & Input Labels
- **Explicit Labels**: All form inputs have associated `<label>` elements or `aria-label` attributes where visual labels are not present (e.g., the search bar input).
- **Validation Feedback**: Error messages (e.g., "Password does not match") are announced and displayed clearly near the relevant input field, rather than relying solely on color changes.
- **Placeholder Text**: We ensured that placeholders provide helpful hints but do not replace actual labels.

## 4. Visual Accessibility
- **Color Contrast**: We adhered to WCAG 2.1 AA standards for color contrast. Text is primarily dark (`#1a3635`) on light backgrounds, ensuring readability for users with low vision.
- **Visual Cues**: We do not rely on color alone to convey information. For example, booking statuses use both color (Green/Red) and text labels ("Accepted"/"Declined"), often accompanied by icons.
- **Sizing**: Text sizes are relative and responsive, and touch targets (buttons) are sized appropriately for users with motor impairments.

## 5. ARIA Attributes
- **Status Announcements**: We use `aria-live` regions (via Ant Design's `message` component) to announce dynamic updates like successful bookings or errors without requiring page reloads.
- **Icons**: purely decorative icons are hidden from screen readers or given appropriate `aria-label` descriptions when they serve as interactive buttons (e.g., the "Back" arrow button).
